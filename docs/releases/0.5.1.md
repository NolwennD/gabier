## New in 0.5.1

- **A call of the MCP server acts on the project of its file.** A path (`file`, `files`) must be absolute: a relative path
  is refused as an invalid value that asks for an absolute one (the server used to make it absolute from the folder it was
  started in, which is not the project of a worktree that the agent entered afterwards). The daemon of the project of the
  file answers (the nearest folder above it with a `.git`), one daemon per project; files of one call in two projects are
  refused. The command line is unchanged. See [`mcp`](https://github.com/NolwennD/gabier/blob/v0.5.1/docs/commands/mcp.md).
- **`gabier mcp` keeps answering while a call waits.** `ping` and `status` are answered during a call that waits for the
  daemon (a cold start takes about a minute), a call with a `progressToken` gets progress notices with the state of jdtls,
  `notifications/cancelled` ends a call, and a call ends with `daemon-timeout` after 11 minutes. Ids are echoed as received.
- **The daemon stops by itself** after 60 minutes with no request (`GABIER_IDLE_TIMEOUT`, in whole minutes, `0` turns it
  off), with jdtls and its workspace. `gabier status` says the delay and the time left. A command sent to a daemon that is
  stopping starts a new one; the refusal `daemon-stopping` appears only when that does not work. See
  [`daemon`](https://github.com/NolwennD/gabier/blob/v0.5.1/docs/daemon.md).
- Concurrent first calls no longer start several daemons.
- Inside: a release needs `docs/releases/<version>.md`, which is where these notes come from.
