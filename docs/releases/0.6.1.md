## New in 0.6.1

- **A command made right after jdtls is ready is no longer answered from stale files.** jdtls announces that it is ready,
  then builds the project and only afterwards registers the files it watches, about two seconds later. `diagnostics`
  waited for that; `rename`, `rename-token`, `references`, `move`, `create`, `organize-imports`, `cleanup`, the `extract-*`
  commands, `inline`, `actions`, `apply-action` and `affected-tests` did not, and could be refused as
  `language-server-no-such-symbol` (or `language-server-invalid-name`) at a position that holds the symbol, or work from a
  file that had changed on disk without jdtls being told. Every command that touches files now waits for that
  registration, so the first command after `gabier start` (or after the daemon starts by itself) takes about two seconds
  longer and is answered correctly. The wait ends with a timeout refusal if jdtls never registers. See
  `gabier help status`.
- Inside: the integration test of the rename on a real jdtls, which failed once on the release build of 0.6.0, no longer
  can.
