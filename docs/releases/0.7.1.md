## New in 0.7.1

- **The first command in a checkout that holds nested worktrees or a `node_modules` no longer tells jdtls of their
  files.** The daemon looks at the files of the project before it starts jdtls and at each request, and tells jdtls of
  those that are new, changed or gone. That scan now leaves out, with everything below them, the folders named
  `node_modules` (by name only: a source package of that name is left out too) and the folders that have a `.git` of their
  own, file or folder (a nested worktree such as `.claude/worktrees/*`, a git submodule, a cloned repository). Before, a
  checkout that held several worktrees and their `node_modules` sent tens of thousands of file changes to jdtls with the
  first command, which made it slower. No command, option or refusal changes.
- **A change inside a git submodule or a nested repository that is part of the Java project is no longer told to jdtls.**
  Such a folder has a `.git` of its own, so the scan leaves it out. jdtls still reads these folders for its own import.
- **After the upgrade, a daemon that starts on the state an earlier version kept reports once, as deleted, the files of
  that state that lie below a folder now left out.** Nothing is lost: the files are no longer watched, and the state is
  rewritten when the daemon stops. See `docs/daemon.md`.
