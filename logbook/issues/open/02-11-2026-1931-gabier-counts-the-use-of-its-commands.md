# gabier counts the use of its commands

Opened: 02-11-2026 19:31

The user can see which commands the agents call, how often each is refused and why, and how long each takes: the
frictions that `.claude/rules/dogfooding.md` turns into tickets, measured instead of remembered. Event sourcing
(decision of the user, 02-11-2026): every request the daemon answers appends an event to a local log that is never
rewritten, and the statistics are projections computed when they are read. An event has an `id` (UUIDv7, so the logs of
several daemons merge by sorting), a type, a schema version, and its data: the method, dry run or not, the outcome
(success, key of the refusal, or error), the duration, a hash of the project path; never a file content or a symbol
name. One file per daemon run under `$XDG_STATE_HOME/gabier/events/`, so no two processes write the same file. A new
context (`usage`): events, projections and the port of the log in a pure domain, the JSON-lines file as adapter, the
writing in `RequestHandler.call`, the reading in the cli. The modules stay on release 25 (decision of the user): the
UUIDv7 is generated by a class of our own, `@Deprecated` from the start, whose Javadoc says to replace it with
`UUID.ofEpochMillis` (Java 26) when the release moves; it follows RFC 9562 and the contract of that method, and is
written from them, not copied from the JDK source (GPLv2 with the Classpath Exception; gabier is Apache-2.0).

Done when:
- each request the daemon answers appends one event with the data above, refusals and errors included;
- `gabier stats` prints, per command, the number of calls, of refusals by key and of errors, read from every log, with
  no daemon running;
- the UUIDv7 class gives the version and variant bits of RFC 9562 and ids that sort with their milliseconds;
- the help and `docs/` describe `gabier stats` and the log; `bin/ci` passes.

Depends on: rename-the-base-package.
